## Scope and interpretation

Preserve the existing architecture, opt-in faithful mode, generic bucket-elevator pilot, immutable upstream pin, and the ten-task sequence. The first increment selects no more than three substantive gains; this does not cancel the remaining research, documentation, testing, skill-evaluation or delivery obligations. Phase B remains gated. No new renderer package, external skill, deployment or permission is selected by this research.

This matrix is an implementation checklist, not proof of completion. “Covered” means an existing contract or planned task owns the requirement; runtime claims require executed evidence. “Active” means still owed. “Conditional” activates only when its specified capability is adopted. “Source-deferred” means intentionally outside this round. Completed mathematical/source checks are stated narrowly.

Next task-local technical refinements: optional strict-isometric precision, presentation-aware selection, and stronger product-material/color diagnostics through the existing Phase B path. Apply the sequencing section below; these do not replace the earlier accepted three gains. Existing evidence, causal readouts, canonical static descriptions and mobile inspection QA remain required and must not be reimplemented as new systems.

Primary-source research has completed the bounded projection, surface/material, color/shadow, lifecycle, picking/clipping and skill-format/evaluation questions. Actual pilot diagnosis, browser comparisons, installed-version API verification, device measurement and authoring evaluation remain execution work.

## Genuine blockers versus intentional deferrals

- **Actual pipeline dependencies:** until Tasks 3–6 produce a runnable pilot, visual defect diagnosis/captures are pending prerequisites, not evidence that no defects exist. Until Phase B pilot passes, product PBR implementation remains gated.
- **Real-machine evidence:** manufacturer identity/measurements/material evidence absent; no prompt fills that gap. E0 demonstration and implementation testing can continue.
- **Human review/device results:** qualified mechanical validation and actual-device performance require real evidence/reviewer/hardware; subjective appearance review unperformed must be labeled. This does not block generic SVG implementation.
- **Rights/security:** unknown asset rights block that asset; permitted analytic/local alternatives may permit work to continue. Persistent access/deploy/publication remain subject to separate authorization.
- **Not blockers:** avoiding city editor, flood-fill implementation without use, native CAD, path tracing/offline, complex shaders, mandatory external textures and ten separate packages is explicitly compliant deferral, not failure to satisfy the user's request.
