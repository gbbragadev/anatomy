# Machine contracts 0.1.0

The opt-in public entry point is `fidelity/index.mjs`; types are in `types.d.ts`. Claims require an explicit `unit` for all their acceptance fields, or `null` when unknown. Standalone quantities use the same required/closed shape as manifest quantities, including all provenance and explicit nullable acceptance fields. Canonical SI outputs are not abbreviated raw inputs to normalize again. Install the isolated package with `npm --prefix fidelity ci`. Legacy imports do not load Ajv.

- `validateMachine(raw)` returns either a complete normalized machine or diagnostics without an executable partial value.
- `normalizeQuantity(quantity, dimension)` preserves `null`, converts registered units to SI and retains the original quantity, source uncertainty, manufacturing tolerance, project tolerance and numerical acceptance separately. A nonzero value or acceptance field that converts to zero returns `QUANTITY_UNDERFLOW` with its field path and no partial normalized value; explicit zero and representable subnormals remain supported.
- `canonicalHash(data)` sorts object keys and only the manifest's declared top-level ID collections. Commands, polygon vertices, compound component sequences and unknown arrays retain order.
- `evaluateClaims(spec, checks)` returns separate construction, kinematic, process and appearance decisions per claim. A submitted check must match its declared criterion’s aspect, complete claim/source sets and physical part scope when supplied. Claims and criteria must link reciprocally. F0 needs listed illustrative assumptions. F1 is limited to selected dimensional construction comparisons against measurement/drawing/CAD evidence, with a declared validity scope, unit-bearing uncertainty, physical acceptance and evidence-located numeric comparisons. F2 is limited to kinematics, with compatible numerical acceptance and evidence-located traces over defined ticks/states. F3 remains unavailable because this contract has no independent-trial/prediction-domain evidence record. An explicit human review record is also required for supported non-illustrative levels. This function checks the recorded review, not the person's qualification or source authenticity.
- `invalidateClaims(spec, changedSourceIds)` traverses declared source, material/asset, definition/instance, part/frame/interface/constraint, criterion and claim dependencies, including nested Quantity sources. It returns sorted dependent claim, physical part and check IDs. Domain-parameter sources use explicit dependency links with known affected targets; empty links or links with only unknown targets do not establish scope, so they conservatively invalidate the machine contract.
- `auditVisibleText(spec, checks)` checks claim/source-location mappings and release suitability for captions, tooltips, static alternatives and report prose. Illustrative text must explicitly label its nature. Targeted unsafe real-capacity assertions are guarded in both assertion and illustrative modes. Mapping and targeted unsafe-assertion checks do not replace a human factual review of arbitrary prose.

The complete minimal fixture is `tests/fidelity/fixtures/minimal-valid.json`. The spec's abbreviated JSON is deliberately incomplete and invalid. Input is strict JSON-compatible plain data with no extra fields, callbacks or raw markup. Asset entries are local references only; validation never fetches bytes. Missing rights retain the entry but mark redistribution unavailable.

## Canonical representation

Positions and geometric lengths are metres. Angles and revolute limits are radians. Frames are right-handed and Z-up; local rest transforms remain local. Source quaternion norm error up to `1e-9` is accepted and normalized once to a canonical unit quaternion, retaining the exact source pose/unit in `.original`; larger norm errors and zero quaternions fail. Original frame/length metadata is retained in `originalFrame` and `.original`. Assets explicitly retain their source coordinate conventions for later ingestion. Criterion expected values and manufacturing/project/numerical tolerances, plus unit-bearing claim uncertainty/acceptance, are normalized together and retain original unit metadata. Physical manufacturing/project tolerances are kept separate from numerical tolerances. Unknown or incompatible units/uncertainty cannot support promotion; uncertainty that exceeds or crosses the intended acceptance also prevents approval. Raw and normalized evidence evaluation requires finite canonical quantities, submitted comparisons and residual/uncertainty arithmetic; overflow produces not-evaluated diagnostics with the relevant field or result path. Initial fields ending `_s`, `_m`, `_mps`, `_rad` or `_kg` are already SI regardless of the input frame's drawing unit.

Boxes use full dimensions and a centred origin. Cylinders are centred on local Z with full `length`. Prisms use ordered local XY vertices, centred extrusion along local Z and full `height`. Compound component poses are local to the compound, with position lengths expressed in the machine input frame unit before normalization; primitive dimensions carry their own explicit unit. Positive uniform part scales remain explicit for the assembly compiler to apply once. Geometry, audit geometry and contact geometry remain distinct and linked to the physical part.

The transform tree is `parts[].parentId`. Joints identify separate parent/child frames; moving-joint axes are normalized in the joint frame. Ratio and closure constraint records are separate from the parent tree; contract acceptance does not claim that a generic closure solver exists. The [assembly compiler](../assembly/README.md) checks interface compatibility/alignment and geometry topology while preserving separate solver capability outcomes.

Only the `belt-bucket/kinematic-mass-v1` contract namespace is recognized. The contracts module exports no model or recipe; the recipe is in [`recipes/belt-bucket`](../../recipes/belt-bucket/README.md) and the model in [`fidelity/model`](../model/README.md). The fixture's centre distance is computed without rounding; all its machine information remains E0 assumptions. Recognition cannot establish real dimensions, calibrated capacity, safety, wear or operational prediction.
